# 三种中文长文听稿请求

把下面一段复制给已经启用 `listening-script` 的 Agent，再替换方括号。没有启用技能时也可以用请求描述任务。这里是请求模板，不是已经生成的节目，也不是事实来源。

只提供你有权使用的资料。模板不会自行上网、上传文件、调用语音接口或生成音频；你使用的 Agent 是否联网、如何处理输入，仍由其工具和设置决定。

## 我有读书笔记，想听一篇完整解读

适合：自己写的读书笔记、获授权的文章，或者可以使用的公共领域原文。书名本身不足以证明 Agent 读过原书。

```text
请用 listening-script，把下面的材料整理成中文书籍解读听稿。

书名与版本：[书名、作者、译者或版本；不知道的写不知道]
材料：[粘贴自己的读书笔记或可使用的原文；附可核对的章节信息]
想重点听的问题：[例如：这本书怎样解释一个具体矛盾？]
目标篇幅：[例如：约4000中文字；如果原文不足，请先说明，不用重复句子凑字数]
改写范围：[完整保留细节／可以删掉指定部分／只校对错字]
剧透要求：[可以讲结局／不讲结局]

把作者的原意、我笔记里的理解、你的解释分开；不要编造原书引文、人物经历或未提供的章节。将表格与概念关系解释成能听懂的句子，保留原有数字和不确定性。只有在我允许的范围内才做摘要。

输出节目标题、可单独朗读的正文，以及另一份来源与编辑说明。正文不念网址，不出现“见上图”。如果材料只覆盖部分章节，说明覆盖范围，不声称解读了整本书。
```

试用时先比较一段原文和一段听稿，检查观点归属有没有变化。不能因为口语更顺，就把“作者认为”改成一个已经证实的结论。

## 我想听指定时间范围内的AI资讯

适合：有日期和原始链接的公告、产品文档、采访或新闻材料。实时资讯不能靠模型记忆补齐。

```text
请用 listening-script，基于下面的资料编写一期中文AI资讯听稿。这是从资料写新稿，不是原文逐字校对。

截止日期与时区：[例如：2026年10月4日，北京时间]
覆盖区间：[明确起止日期，不只写“最近”]
读者关注：[例如：普通人能使用的功能变化；不讲未经验证的商业预测]
资料：[每条写来源、原始链接、发布日期、相关原文；没有资料就留空]
目标篇幅：[例如：约3000中文字]

只使用覆盖区间内且有来源的资料，区分“宣布”“开始测试”“已正式开放”和“计划上线”。价格、地区、设备或账户限制按来源保留；不把发布方宣传当独立效果证据。

没有联网或不能读到原文时，明确哪些资料尚未核实，先给缺失清单；不要为了凑一周资讯编造事件。两个媒体转述同一公告时合并为一条，保留最接近原始信息的来源。

输出标题、可独立朗读的正文，以及不需要朗读的来源清单。把日期与适用范围讲清楚，网址放到单独清单。不要自动发布或把我的输入传给额外服务。
```

选题前可以先做资料清单。来源不足时，一期少讲几个确证事件，通常比拼凑热闹的“十大新闻”更容易核对；篇幅不足要如实说明。

## 我想听一个历史问题的来龙去脉

适合：围绕明确问题，用机构史料、原始材料和可靠研究组织一篇讲解稿。来源支持制度变化，不一定支持“世界第一次”。

```text
请用 listening-script，围绕下面的问题写一篇中文历史听稿。

问题：[例如：为什么铁路推动了标准时间制度？]
资料：[粘贴已经读到的原文片段、机构名称、链接、日期与章节]
关注的地区和时期：[例如：十九世纪美国；不要无依据扩展到全世界]
目标篇幅：[例如：约2500中文字]
叙述要求：[可以用明确标为假设的例子解释概念，不虚构真实人物的对话和心理]

区分早期想法、行业采用、国际会议和法律实施。不同日期可能指不同阶段，不能为了故事流畅合成一个年份。资料没有证明最早起源时，不写“首次发现”。相互冲突的记载另列，不自行选择更精彩的说法。

先列一份关键事实与来源对应表，再输出可独立朗读的正文和单独来源说明。事实表用于核对，不放进朗读正文。不要编造历史引语、戏剧化现场或未取得的档案。
```

可核对的完整例子：

- [铁路与标准时间：听稿、来源、事实表和8分05秒音频](https://godgod126.github.io/listening-script-kit/learning/railway-time/)
- [平均数与中位数：原创虚构练习、听稿和8分17秒音频](https://godgod126.github.io/listening-script-kit/learning/mean-median/)

这些音频是Mac端模型生成的AI合成示范，不是iPhone录音或设备性能测试。不同题材的字数和实际时长不同，模板中的篇幅不保证固定分钟数。

## 听稿之后怎么收听

先保存正文与来源说明，保留自己核对过的版本。可以使用你选定的文字转语音工具；这份技能本身不合成声音，也不会在生成稿里自动插入产品广告。

本项目由「自听」MyListen开发者 Ryan Zhu 提供，AI辅助编写。`listening-script` 与这些原创请求采用MIT许可，可独立使用；第三方原文依其版权条件使用。

「自听」负责把自己的文字在iPhone或iPad本地变成音频并收听，支持保存进度、锁屏播放与续听，无订阅、无广告；完整功能通过App内购买解锁。免费技能与App商业条款分别适用。
